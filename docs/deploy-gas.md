# Apps Script 배포 안내

신청 데이터는 구글 시트 하나에 저장하고, 그 시트를 Apps Script 프로젝트 두 개가 같이 쓴다.

| 프로젝트 | 종류 | 실행 계정 | 접근 | 하는 일 |
|---|---|---|---|---|
| **api** | 스프레드시트 '2026 RFW 접수 DB' 에 묶인 스크립트 | 나(배포한 계정) | 모든 사용자(익명) | 참가자 신청·조회·수정·취소·링크 재발송. Cloudflare Worker 만 호출 |
| **admin** | 독립 스크립트 | 접속한 사용자 | Google 계정이 있는 모든 사용자 | 관리자 화면. 허용 명단에 없는 계정은 '권한이 없어요' 화면만 받음 |

코드는 `gas/shared/*.gs`(공통) + `gas/api/` · `gas/admin/` 에 있고, `node tools/build-gas.mjs` 가 `gas/dist/api`, `gas/dist/admin` 으로 합쳐 준다(관리자 화면 `Admin.html` 도 이때 만든다). clasp 설정은 `gas/api/clasp.json`, `gas/admin/clasp.json` 에 있고 빌드가 `gas/dist/<프로젝트>/.clasp.json` 으로 복사한다.

## 0. 올리기 전에 확인

```bash
node tools/test-gas.mjs        # 가짜 시트로 서버 코드 전체 테스트 — PASSED 가 나와야 한다
```

## 1. 스프레드시트와 프로젝트

이미 만들어져 있다(운영 계정 드라이브).
- 스프레드시트 '2026 RFW 접수 DB' — api 프로젝트가 여기에 묶여 있다(확장 프로그램 → Apps Script).
- admin 프로젝트 — 독립 Apps Script 프로젝트.

새로 만들어야 할 때: 빈 스프레드시트를 만들고 확장 프로그램 → Apps Script 로 api 프로젝트를, script.google.com 에서 admin 프로젝트를 만든 뒤, 각 프로젝트의 스크립트 ID(프로젝트 설정 → ID)를 `gas/<프로젝트>/clasp.json` 의 `scriptId` 에 넣는다.

**스프레드시트 ID** 는 시트 주소 `https://docs.google.com/spreadsheets/d/<여기>/edit` 의 가운데 값이다.

## 2. 코드 올리기 (clasp)

처음 한 번 운영 계정으로 로그인한다(`rfw` 라는 이름으로 저장).

```bash
npx @google/clasp@3.4.1 --user rfw login
```

> Apps Script API 를 켜 둬야 push 가 된다: https://script.google.com/home/usersettings → 'Google Apps Script API' 사용.

올릴 때마다:

```bash
node tools/build-gas.mjs && cd gas/dist/api   && npx @google/clasp@3.4.1 --user rfw push -f
node tools/build-gas.mjs && cd gas/dist/admin && npx @google/clasp@3.4.1 --user rfw push -f
```

`gas/dist/` 는 매번 새로 만들어지므로 그 안의 파일을 직접 고치지 않는다.

## 3. 스크립트 속성

각 프로젝트 편집기 → 프로젝트 설정(톱니) → 스크립트 속성.

| 속성 | api | admin | 값 |
|---|:-:|:-:|---|
| `SHEET_ID` | 자동 | **필수** | 스프레드시트 ID. api 는 비어 있으면 `setup()` 이 묶인 시트의 ID 로 채운다 |
| `GAS_KEY` | 자동 | – | Worker 만 아는 비밀값. 비어 있으면 api `setup()` 이 만들어 실행 로그에 보여 준다 |
| `SITE_URL` | **필수** | – | 참가자 화면 주소(예: `https://….pages.dev`). 문자 속 수정 링크 = `{SITE_URL}/?t={토큰}` |
| `ADMIN_EMAILS` | – | **필수** | 관리자 구글 계정, 쉼표로 구분. 화면에 보일 이름은 `ops@x.com:운영팀` 처럼 콜론 뒤에(선택) |
| `SMS_PROVIDER` | 나중에 | – | 문자 업체가 정해지면. 비어 있으면 문자는 실행 로그에만 남는다(스텁). 넣기 전에 `Api.gs` 의 `smsProviderSend_` 를 구현해야 한다 |
| `PURGE_CONFIRM` | – | 파기 때만 | `YES` 일 때만 `purgePersonalData()` 가 실행되고, 실행 뒤 자동으로 지워진다 |

## 4. setup 실행

1. **api** 편집기에서 함수 `setup` 선택 → 실행. 처음에는 권한 승인 창이 뜬다(시트 읽기·쓰기, 트리거 관리).
   - 탭 6개(신청·변경이력·설정·프로그램·관리자로그·방문집계)와 머리행을 만들고, 설정·프로그램 탭에 `web/js/config.js` 와 같은 기본값을 넣는다.
   - 실행 로그에 나온 `GAS_KEY` 를 Worker 비밀값으로 넣는다(아래 6).
   - 여러 번 실행해도 안전하다(있는 탭·값은 건드리지 않고 서식만 다시 맞춘다).
   - 처음부터 있던 '시트1' 탭은 지워도 된다.
2. (선택) api 에서 `installTriggers` 실행 → 매일 03시 시트 사본 백업, 매시간 방문수 반영 트리거를 만든다. 사본은 실행한 계정의 내 드라이브 최상위에 '… 백업 YYYY-MM-DD HH:mm' 으로 생긴다.
3. **admin** 편집기에서 `SHEET_ID`, `ADMIN_EMAILS` 를 넣고 `setup` 실행 → 속성과 탭을 확인만 한다. 문제가 있으면 무엇을 고칠지 한국어로 알려 준다.

## 5. 웹앱 배포

각 편집기 → 배포 → 새 배포 → 유형 '웹 앱'.

| | 다음 사용자 인증정보로 실행 | 액세스 권한이 있는 사용자 |
|---|---|---|
| api | 나 | 모든 사용자 |
| admin | 웹 앱에 액세스하는 사용자 | Google 계정이 있는 모든 사용자 |

(`appsscript.json` 에 같은 값이 들어 있다.) 배포하면 `…/exec` 로 끝나는 주소가 나온다.
- api 주소 → Worker 설정(아래 6).
- admin 주소 → 관리자들에게 전달.

**코드를 고친 뒤**에는 push 만으로는 웹앱에 반영되지 않는다. 배포 → 배포 관리 → 연필 → 버전 '새 버전' → 배포. 이렇게 하면 주소가 바뀌지 않는다(새 배포를 만들면 주소가 바뀐다).

## 6. Worker 연결

Worker 비밀값에 `GAS_KEY`(api 실행 로그의 값)와 api 웹앱 주소를 넣는다. Worker 는 참가자 요청 본문에 `k` 를 붙여 api 주소로 POST 하고, 302 리다이렉트를 따라가 받은 JSON 을 그대로 돌려준다(docs/api.md).
- `GAS_KEY` 를 바꾸려면 api 스크립트 속성에서 지우고 `setup` 을 다시 실행한 뒤 Worker 비밀값도 바꾼다.

## 7. 관리자 추가

관리자 한 명마다:
1. 스프레드시트를 그 구글 계정에 **편집자로 공유**한다(관리자 화면은 그 사람 권한으로 시트를 읽고 쓴다).
2. admin 스크립트 속성 `ADMIN_EMAILS` 에 계정을 더한다(배포를 다시 할 필요 없음).
3. 관리자가 admin 주소에 처음 들어가면 '이 앱은 Google에서 확인하지 않았습니다(확인되지 않은 앱)' 화면이 뜬다. **고급 → '…(으)로 이동(안전하지 않음)' → 허용** 을 눌러야 한다. 요청 권한은 스프레드시트 읽기·쓰기와 이메일 주소 확인이다. 한 번만 하면 된다.

명단에 없는 계정은 동의 화면을 지나도 '권한이 없어요' 화면만 받고, 모든 관리자 함수가 `FORBIDDEN` 을 돌려준다. 관리자를 뺄 때는 `ADMIN_EMAILS` 에서 지우고 시트 공유도 해제한다.

로그인(관리자 화면 열기)·내보내기·수정·설정 변경은 관리자로그 탭에 남는다.

## 8. 운영 중 주의

- **'신청' 탭의 행을 지우거나 정렬하지 않는다.** 보기 정렬은 '필터 보기'를 쓴다. 상태(신청/취소)를 시트에서 직접 바꾸면 변경이력이 남지 않아 관리자 화면 일별 누적이 어긋난다 — 관리자 화면에서 바꾼다.
- 오픈 전 테스트 신청은 신청·변경이력·방문집계 탭의 데이터 행을 지워 정리한다(머리행은 남긴다). 그러면 접수번호가 0001 부터 다시 시작한다.
- 관리자 일별 현황 메모(예: '1차 홍보 문자')는 설정 탭 `dailyNotes` 값에 `{"2026-12-01":"접수 오픈 · 1차 홍보 문자"}` 처럼 넣는다.
- 관리자 화면에서 바꾼 설정은 참가자 화면에 최대 30초 뒤 반영된다(마감·정원 판단은 신청 때 바로 한다).
- api 는 '나로 실행'이라 동시 실행이 한 계정 한도(약 30개) 안에서 돈다. 신청 저장은 잠금으로 한 줄씩 처리되며, 잠금을 20초 안에 못 잡으면 '신청이 몰리고 있어요' 오류를 돌려준다.
- api 와 admin 은 서로 다른 프로젝트라 잠금을 공유하지 않는다. 같은 신청 건을 참가자와 관리자가 같은 순간 고치면 나중 저장이 이긴다(접수번호 발급은 api 에서만 하므로 겹치지 않는다).

## 9. 보유 기간 만료 후 파기

1. 결과보고용 최종 내보내기를 끝낸다.
2. admin 스크립트 속성 `PURGE_CONFIRM` = `YES`.
3. admin 편집기에서 `purgePersonalData` 실행(실행 계정이 `ADMIN_EMAILS` 에 있어야 한다).
   - 신청 탭의 이름·소속·휴대전화번호·토큰을 비우고(접수번호·일시·상태·참석일·언어·유입경로는 통계용으로 남김), 변경이력에서 이름·소속·번호 변경 내용을 지운다. 관리자로그에 '파기' 행이 남는다. 되돌릴 수 없다.
4. 따로 지워야 하는 것: 백업 사본(내 드라이브 '… 백업 …' 파일)과 드라이브 휴지통, 스프레드시트 버전 기록(필요하면 사본을 만든 뒤 원본 삭제), 관리자들이 내려받은 엑셀·CSV 파일.
5. `installTriggers` 로 만든 트리거는 api 편집기 → 트리거 메뉴에서 지운다.
